# YOLO 训练结果 · 术语速查

> **用途**：把一个 `runs/detect/<run>/` 目录读成人话。看结果时卡在哪个名词，查这里。
> **一键读结果**：`python tools/summarize_run.py --run <run名>` —— 自动算最佳轮次、判过拟合、给下一步建议。
> **适用**：`ultralytics 8.4.x`（YOLOv8 / YOLO26 通用；两代差异见第 4 节）
> **样本数据**：全文的实测数字都来自 `runs/detect/train-coco8/`（yolo26n + coco8，100 轮）
> **只想看“症状 → 改哪个参数”？直接跳 [第 12 节 调参处方](#12-调参处方症状--参数)**

## 0. 30 秒版本

```text
1. 先看 args.yaml       —— 这是什么实验？（epochs/patience 会不会强制过拟合）
2. 再看 results.csv     —— 最佳轮次是哪一轮？（不是最后一轮！）
3. 再看 results.png     —— train 降 + val 升 = 过拟合
4. 再看 confusion_matrix —— 最右列=误检，最后一行=漏检
5. 最后看 val_batch0_labels vs _pred —— 用眼睛确认失败长什么样
```

**必背 6 个词**

| 词 | 一句话 |
|---|---|
| IoU | 两个框的重叠比例，≥0.5 就算“框对了” |
| P（精确率） | 报出去的框里，有多少是真的 → 惩罚**误检** |
| R（召回率） | 真的目标里，找到了多少 → 惩罚**漏检** |
| mAP50-95 | 最严的综合分，**汇报就用它** |
| `val/` loss 反向上扬 | 过拟合的**铁证** |
| 混淆矩阵 | 对角线=对的，最右列=误检，最后一行=漏检 |

## 1. 一次训练产出什么

`runs/detect/<run>/` 里的东西，按“该不该看”排序：

| 文件 | 回答什么问题 | 优先级 |
|---|---|---|
| `args.yaml` | **这到底是什么实验**（唯一可信的参数记录） | ★★★★★ |
| `results.csv` | 每个 epoch 的精确数字，用来找最佳轮次 | ★★★★★ |
| `results.png` | 曲线**形状**：收敛了？过拟合了？ | ★★★★★ |
| `labels.jpg` | **数据体检**：类别平不平衡、框多大 | ★★★★ |
| `confusion_matrix_normalized.png` | 错误集中在**哪个方向**（误检/漏检/混淆） | ★★★★ |
| `val_batch0_labels.jpg` / `_pred.jpg` | 真值 vs 预测，肉眼验尸 | ★★★★ |
| `BoxPR_curve.png` / `BoxF1_curve.png` | 选 `conf` 工作点（F1 最高处） | ★★★ |
| `train_batch*.jpg` | 数据增强后的图长什么样（看 mosaic 拼图） | ★★★ |
| `BoxP_curve.png` / `BoxR_curve.png` | P/R 随置信度怎么变 | ★★ |
| `weights/best.pt` | 最佳权重 → **推理/导出都用它** | — |
| `weights/last.pt` | 最后一轮 → 只用于 `resume` 或排查 | — |

**目录里没有的东西**（得自己测）：延迟、显存、域外误检率 → `tools/bench_latency.py` + 自己拼一张对比图。

> ⚠️ 结尾那批图（混淆矩阵、PR 曲线、`val_batch*_pred.jpg`）**是用 `best.pt` 生成的**，不是在最后一轮生成。
> 源码依据：`engine/trainer.py::final_eval()` 里 `model = self.best if self.best.exists()`。

## 2. `results.csv` 列名词典

**先立框架**——一行 CSV 是一份体检报告，同时记了三套数字：

| 前缀 | 在哪算 | 给谁看 | 方向 |
|---|---|---|---|
| `train/` | **训练集** | 优化器（靠它更新权重） | 越小越好 |
| `val/` | **验证集** | 你（检验有没有背题） | 越小越好 |
| `metrics/` | **验证集** | 你（考试分数） | 越大越好 |
| `lr/` | — | 排查用 | 看趋势 |

`(B)` = **B**ox（框）。因为还有分割 `(M)`、姿态 `(P)`，正式命名带后缀。

| 列名 | 中文 | 定义 / 直觉 | 方向 | train-coco8 实测（ep1 → ep100） |
|---|---|---|---|---|
| `epoch` | 轮次 | 训练集完整过一遍 = 1 轮 | — | 1 → 100 |
| `time` | 累计秒 | 从开训到本轮结束 | — | 7.16 → 63.67（≈0.64 s/轮） |
| `train/box_loss` | 定位损失 | 框画得**偏不偏**、大小对不对 | ↓ | 1.331 → 0.537 |
| `train/cls_loss` | 分类损失 | 框里**是什么东西**猜得对不对 | ↓ | 2.589 → 0.561 |
| `train/dfl_loss` | 分布焦点损失 | 框边界刻画得多细（**只有 v8 有**） | ↓ | — |
| `train/l1_loss` | 坐标 L1 损失 | 同上，YOLO26 去掉 DFL 后用它 | ↓ | 0.0138 → 0.0043 |
| `metrics/precision(B)` | 精确率/查准率 | 报的框里有多少是真的 = TP/(TP+FP) | ↑ | 0.563 → 0.512 |
| `metrics/recall(B)` | 召回率/查全率 | 真目标找到了多少 = TP/(TP+FN) | ↑ | 0.963 → 0.550 |
| `metrics/mAP50(B)` | IoU0.5 的 mAP | 宽松分，容易虚高 | ↑ | 0.941 → 0.672 |
| `metrics/mAP50-95(B)` | 严格 mAP | IoU 0.5~0.95 十档平均，**最该信** | ↑ | 0.675 → 0.459 |
| `val/box_loss` | 验证定位损失 | 验证集上的定位误差 | ↓ | 1.584 → **1.956 ↑** |
| `val/cls_loss` | 验证分类损失 | 验证集上的分类误差 | ↓ | 0.955 → **1.225 ↑** |
| `val/dfl_loss` / `val/l1_loss` | 验证边界损失 | 同上 | ↓ | 0.0116 → **0.0173 ↑** |
| `lr/pg0` `pg1` `pg2` | 学习率 | 三个参数组各自的学习率（warmup 期从 0 爬） | 看趋势 | 0 → 3.9e-05 → 2.4e-06 |

**读法铁律：`train/` 和 `val/` 必须成对看。**

| train loss | val loss | 判断 | 该干什么 |
|---|---|---|---|
| ↓ | ↓ | **健康** | 继续训，等平台期 |
| ↓ | ↑ | **过拟合**（背题了） | 减 epochs / 加数据 / 加增强 |
| ↑ | ↑ | 训练异常 | 查 lr、查数据、查标注 |
| 不动 | 不动 | 欠拟合或学习率≈0 | 加 epochs、查 `lr/pg0` |

## 3. 五个底层概念

### ① IoU（交并比）—— `mAP50` 里的 50 就是它

```text
  真值 ┌────────┐
       │   A    │
       │     ┌──┼─────┐
       └─────┼──┘     │
             │   B    │
             └────────┘

IoU = (A ∩ B) / (A ∪ B)        完全重合 = 1.0，不碰 = 0
```

- `IoU ≥ 0.5` → 这个框算“对了” → 所以叫 `mAP50`
- `mAP50-95`：要求 IoU 在 0.5、0.55、…、0.95 **十档都表现好**，所以分数低得多，也更可信

### ② TP / FP / FN

| 记号 | 名字 | 大白话 | 在图上长什么样 |
|---|---|---|---|
| TP | 真正例 | 找到了，位置也对 | 框贴着目标 |
| FP | 假正例 | **无中生有**（误检） | 框住空气/背景 |
| FN | 假负例 | **漏掉了**（漏检） | 目标在那儿，没框 |

> 判 TP 的规则：预测框和某个真值框的 `IoU ≥ 阈值`，且类别相同，且没被 NMS 干掉。

### ③ Precision（精确率）= TP / (TP + FP)

> “我报了 10 个目标，其中 6 个是真的” → **P = 0.6**

**惩罚胡乱报框。** train-coco8 最佳轮 P=0.568，意思是报出来的框里约**一半是假的**（大量低分框）。

### ④ Recall（召回率）= TP / (TP + FN)

> “实际有 12 个目标，我找到了 9 个” → **R = 0.75**

**惩罚漏。** 同一轮 R=0.972（几乎不漏），到第 100 轮掉到 0.55（漏了一半）。

**P 和 R 互相拉扯**：`conf` 调高 → 假框少（P↑）、真框也被筛掉（R↓）。所以任何时刻都该问“我要哪个”：
- 比赛里“宁可漏不可错” → 保 P
- 比赛里“不能漏关键目标” → 保 R

### ⑤ AP 和 mAP

```text
把 conf 从 1.0 扫到 0，每一步记一组 (R, P) → 画出 PR 曲线
AP   = PR 曲线下的面积（0~1），衡量"这一个类"学得多好
mAP  = 所有类 AP 的平均（mean AP）
mAP50    = IoU=0.5 时的 mAP
mAP50-95 = 10 个 IoU 阈值各自算 mAP 再平均
```

> **一句话**：P 和 R 是“某一个阈值下的两个数”，mAP 是“所有阈值综合起来的一个数”。
> 汇报看 mAP，选阈值看 PR/F1 曲线。

## 4. 三个 loss 分别管什么

YOLO 同时干三件事，每件事一个损失：

| loss | 管什么 | 打靶比喻 | v8 | 26 |
|---|---|---|---|---|
| `box_loss` | 框的**位置和大小** | 打偏了几环 | ✅ CIoU 类 | ✅ |
| `cls_loss` | 框里**是什么类** | 靶子认错了 | ✅ BCE | ✅ |
| `dfl_loss` / `l1_loss` | 框**边界多精细** | 靶心画得多细 | `dfl_loss` | **去 DFL → `l1_loss`** |

- `dfl_loss`（Distribution Focal Loss）把每条边的位置**当成一个分布**去学，v8 用它
- **YOLO26 移除了 DFL**，改成直接回归的 `l1_loss` → 它的 `results.csv` 里**没有** `dfl_loss` 列
- `cls_loss` 用的是**二分类交叉熵（BCE）**，每个类别独立判断“是 / 不是”

**为什么三个 loss 比一个 mAP 有用**：mAP 掉了说不清原因；看 loss 就知道——
`box_loss` 高 = 框不贴合，`cls_loss` 高 = 类别分不清。

## 5. `results.png` 怎么看

十个子图，真正要看的只有 4 个：

| 子图 | 健康的样子 | train-coco8 实际 |
|---|---|---|
| `train/box_loss` `train/cls_loss` `train/dfl_loss` `train/l1_loss` | 平滑下降 | ⚠️ 下降但抖动大（cls 尖峰到 3.0）= lr 相对数据量偏大 |
| **`val/box_loss` `val/cls_loss`** | 跟着 train 一起降 | ❌ 第 21 轮见底（1.55）后**掉头向上**，末轮 1.96 |
| **`metrics/mAP50-95(B)`** | 爬升后走平台 | ❌ 第 2 轮见顶，第 40 轮**断崖**，最后在 0.45 躺平 |
| `metrics/precision/recall` | 稳定高位 | ❌ P 0.88→0.51，R 0.97→0.55 |

**口诀**：`train 降 + val 降 = 健康`；`train 降 + val 升 = 过拟合`；`两个都不降 = 欠拟合`。
`lr/pg0` 那张图顺便看 warmup 和衰减有没有正常发生。

## 6. `labels.jpg` 怎么看（数据体检）

> 画的是**训练集**的标签（不是验证集），而且**跟模型好坏无关**——它诊断的是**数据**。

| 位置 | 内容 | 回答什么 | 危险信号 |
|---|---|---|---|
| **左上** | 类别直方图（x=类别 id，y=框数） | 类别平不平衡？ | 只有几根柱子、高低差很大、某类 0 个 |
| **右上** | 所有真值框叠在归一化坐标系里 | 框的尺寸/位置合理吗？ | 出现撑满画面的怪框=标注错了；全挤在中心=场景单一 |
| **左下** | 框中心 (x, y) 散点 | 目标会不会总在同一个位置？ | 聚成一小团 → 模型能靠“位置”作弊 |
| **右下** | 框宽高 (width, height) 散点 | 目标尺度分布 | 全在 0.15 以下 = 小目标为主 → 得提 `imgsz` |

**train-coco8 的读数**：只有 6 根柱子、总共约 12 个框，最多的一类 4 个 → **类别极不平衡 + 总量太少**；
右上框集中在中部且有一两个超大框 → 大目标主导。**光看这张图就能预言“一定会过拟合”。**

> ⚠️ 横轴是**类别数字 id**（COCO 是 0~79），不是类名。自己 2 类数据集会显示 0 和 1，
> 要对着 `data.yaml` 的 `names` 才知道谁是谁。

## 7. `confusion_matrix_normalized.png` 怎么看

### 轴约定（最容易搞反，先背下来）

```text
              列 = 真值 True（图下方）
      ┌──────┬──────┬──────┬──────────┐
      │      │      │      │background│  ← 真值是"啥也没有"
  行  ├──────┼──────┼──────┼──────────┤
  =   │      │ 格子 │      │          │
  预   ├──────┼──────┼──────┼──────────┤
  测   │      │      │      │          │
  Pre-├──────┼──────┼──────┼──────────┤
  dict│      │      │      │          │
      └──────┴──────┴──────┴──────────┘
              ↑ 对角线 = 预测=真值 = 对的
      Predicted=background 那一行 = 漏检
```

**格子 (行 A, 列 B) 的含义：真值是 B，却被预测成了 A 的次数/比例。**

| 位置 | 亮起来说明什么 | 该改什么 |
|---|---|---|
| **对角线** | ✅ 对的（越亮越好） | — |
| **最后一列**（`background`） | ❌ **误检多**（无中生有） | 补无目标背景图；提 `conf` |
| **最后一行**（`Predicted=background`） | ❌ **漏检多**（视而不见） | 提 `imgsz`；补难例/小目标 |
| 对角线外的某格 | ❌ 系统性把 A 认成 B | 补 A/B 的区分性样本 |

### 两个版本的差别

| 文件 | 每格是 | 什么时候用 |
|---|---|---|
| `confusion_matrix.png` | **次数**（绝对计数） | 想知道“错了多少个” |
| `confusion_matrix_normalized.png` | **比例**（按列归一化，每列和为 1） | **想知道“错了多少比例”← 日常用这个** |

**关键性质**：按列归一化后，**对角线上的值 ≈ 该类别的召回率**。

### 换成你自己 2 类数据集，它长这样（3×3，超好读）

|  | 真值 leaf | 真值 bottle | 真值 无目标 |
|---|---|---|---|
| **预测 leaf** | **28** ✅ | 2 ❌混淆 | 5 ❌误检 |
| **预测 bottle** | 1 ❌混淆 | **25** ✅ | 3 ❌误检 |
| **预测 无目标** | 3 ❌漏检 | 1 ❌漏检 | — |

怎么读：
- 竖着看 leaf 列：`28/(28+1+3)` = **0.875** ← 召回率 87.5%，漏了 3 个
- 横着看 leaf 行：`28/(28+2+5)` = 0.80 ← 精确率 80%，误检 5 个
- 一句话结论：“漏 3 个 + 误检 5 个 + 2 个叶子被认成瓶子” → 直接进误差分析

### train-coco8（80 类）的读数

1. 只有约 6 个格子有颜色（person / dog / horse / elephant / umbrella / potted plant 的对角线）→ 训练集就这几类
2. 非归一化那张里最暗的一格是 **person 行 × background 列 ≈ 200 次** → **把背景当成人报了 200 次**，最大的错误来源
3. person 行在 **dog 列**还有一个浅块 → 少量“狗被判成人”

> ⚠️ **坑**：混淆矩阵是在**极低置信度阈值（≈0.001）**下统计的，所以 `background` 列会堆一堆低分框。
> **它回答“错的方向”，不回答“精度高低”**，别拿这里的 200 去算准确率。
> 另外 80 类的矩阵在缩略图上根本对齐不了行标签 —— 这也说明**为什么你自己的 2~3 类数据集才是练手的好材料**。

## 8. 看到什么 → 改什么

| 你看到的 | 判断 | 动手改什么 |
|---|---|---|
| P 低、R 高 | 假框多 | 提 `conf`；补背景负样本 |
| P 高、R 低 | 太保守、漏检 | 降 `conf`；补难例；提 `imgsz` |
| train 降、val 升 | 过拟合 | 加数据 > 加增强 > 减 `epochs` > 设 `patience` |
| 两个都不降 | 欠拟合/lr 问题 | 加 `epochs`；查 `lr/pg0`；查标注 |
| mAP50 高、mAP50-95 低（差 >0.2） | 框不贴合 | 查标注框是否贴合；关注 `box_loss` |
| 混淆矩阵某一行亮 | A 被认成 B | 补 A/B 区分性样本 |
| 背景列亮 | 误检 | 补负样本；提 `conf` |
| 最后一行亮 | 漏检 | 提 `imgsz`；补小目标 |
| 对角线只有几类亮 | 数据缺类 | 补该类数据 |
| 左上只有几根柱子 | 类别不平衡 | 补少数类 |
| 宽高散点全在 0.15 以下 | 小目标为主 | `imgsz` 640 → 960 |
| `patience ≥ epochs` | 早停被关掉 | `patience` 设成 10~30 |
| val 指标连续多轮**完全不变** | 模型没在学 | 查 warmup / lr 衰减到 0 |
| 换 seed 分数就抖 0.03 | 差异在噪声内 | **别下结论**，先跑 3 个 seed |

**参数敏感度排序（小数据集上）：**
`epochs`（是否收敛） > `imgsz`（小目标/延迟） > 数据增强（`mosaic`/`scale`/`degrees`/`mixup`） > 模型尺寸 > `batch`（会顺带改有效 lr） > `lr`/损失权重（`auto` 已够好，最后再碰）

> ⚠️ `erasing` 和 `auto_augment` **只对分类任务生效**，检测任务里改它们等于没改（官方默认值注释写着 classification only）。

## 9. 实例：`train-coco8` 的判词

`python tools/summarize_run.py --run train-coco8 --table 8` 的输出：

```text
【2】最佳轮次（best.pt 的挑选依据 = fitness = mAP50-95，8.4.x 起）
  ★ best  epoch 2    mAP50 0.9433   mAP50-95 0.6773   ← best.pt 存的是这一轮
    末轮  epoch 100  mAP50 0.6723   mAP50-95 0.4588   ← last.pt 存的是这一轮
    注：如果按 mAP50 挑，会挑到 epoch 13（不是同一个）

【5】判词：过拟合（train 降 + val 升）｜严重：最佳在 2% 处，后 98 轮是负收益
  · 末轮 mAP50-95 0.4588 比最佳 0.6773 低 0.2184
  · patience=100 ≥ epochs=100 → 早停等于被关掉，注定跑满
  · mAP50 0.943 比 mAP50-95 0.677 高 0.27 → 位置不够准，检查标注贴合度
  · 最佳轮 P=0.568 远低于 R=0.972 → 报的框里假框多

【6】下一步该改什么
  1. 加数据（最有效）；数据不动就加增强
  2. epochs 100 → 10 左右
  3. patience 设 10
```

两个细节值得记：

1. **epoch 2、3、4 的分数完全一样（0.67729）**，脚本取的是**较早**的 epoch 2 —— 因为保存逻辑是
   `if best_fitness < fitness`（严格小于），并列时不会覆盖，所以 `best.pt` 就是第 2 轮存的。
2. **best 按 mAP50-95 挑，不是按 mAP50**。这个 run 里两者会挑出不同的轮次（2 vs 13），
   所以汇报时说“最佳”必须说清是哪个指标。

## 10. 常见坑（都是踩过的）

| # | 坑 | 说明 |
|---|---|---|
| 1 | 拿 `conf` / `iou` 当训练参数 | 它们是**推理时**的后处理阈值，改了不重训也能生效 |
| 2 | 拿不同 val 集的 mAP 互相比较 | 分母不同，分数不可比；跨模型比必须在**同一份 val** 上 |
| 3 | 用 `last.pt` 去推理 | 应该用 `best.pt`；`last.pt` 只在 resume / 排查时用 |
| 4 | 只看 mAP 报喜 | mAP50 虚高；域外误检会同时变差（见 `docs/daily/11-3-对照实验与误差分析.md`） |
| 5 | 一次改一堆参数 | 涨了也不知道是谁的功劳；用 `summarize_run.py --compare` 检查 diff |
| 6 | 单次结果就下结论 | 小数据上换 seed 就抖动；先测“噪声地板” |
| 7 | 以为 `runs/` 会进 git | `.gitignore` 里没有；要留证据就拷到 `docs/images/` |
| 8 | 想靠调参救数据 | 8 张图训 100 轮，任何参数都救不了；数据量是天花板 |

## 12. 调参处方：症状 → 参数

> 前面 11 节是“看懂”。这一节是“动手”：**看到某个症状，按顺序改哪几个参数**。
> 记住一句话：**调参不是找最优值，是看到症状后做一个有依据的改动。**

### 12.0 先分清两类参数

| | 什么时候生效 | 参数 | 治什么 |
|---|---|---|---|
| **推理参数** | **改一行立刻生效，不用重训** | `conf` `iou` `agnostic_nms` `max_det` `imgsz`(推理时) | 多个框、误检、漏检 |
| **训练参数** | 要重新训练 | `epochs` `mosaic` `scale` `freeze` `imgsz`(训练时) | 过拟合、欠拟合、学不会 |

> **铁律：能用推理参数解决的，绝不重训。** 90% 的“一个目标多个框”属于这一类。
> 验证方法：`yolo predict ... conf=0.5 iou=0.5`，看框数变不变——不变才说明是训练问题。

### 12.1 总表（先存这张）

| 症状 | 怎么认（看 results.csv / 图） | **先改（免费）** | **再改（重训）** |
|---|---|---|---|
| **过拟合** | `train/` 一路降、`val/` 后半程反向上扬；`best` 早于总轮数 30% | — | 减 `epochs` / 加增强 / `freeze` |
| **欠拟合** | `train` loss 降不下去、mAP 一路在涨、**`best` = 最后一轮** | — | 加 `epochs` / 减增强 / 换大模型 |
| **一个目标多个框** | 同一物体 2~5 个重叠框 | `conf↑` `iou↓` | 加 `epochs`（多半没收敛） |
| **漏检** | 该有的框没有，R 低 | `conf↓`、`imgsz↑` | 加 `imgsz`、补难例 |
| **误检** | 背景上冒框，P 低 | `conf↑` | 补「无目标」背景图当负样本 |
| **框不贴合** | mAP50 高、mAP50-95 低（差 >0.2） | — | 查标注、加 `imgsz` |

### 12.2 过拟合

**认法**：`train/box_loss` 与 `val/box_loss` 走向背离，`best` 落在前 1/3 轮次（train-coco8 就是 best=2/100）。

| 顺序 | 改什么 | 具体值 | 为什么 |
|---|---|---|---|
| 1 | **加数据** | — | 唯一根治 |
| 2 | **减 epochs + 开早停** | `epochs=<best×1.5> patience=10` | 别让它训过峰值 |
| 3 | **加强增强** | `scale=0.7 degrees=10 mixup=0.15` | 增强 = 凭空造数据 |
| 4 | **冻结主干** | `freeze=10` | 小数据集特效药，还更快 |
| 5 | 权重衰减 | `weight_decay=0.001` | 弱，最后试 |

```bash
yolo train model=yolov8n.pt data=datasets/leaves/data.yaml \
  epochs=20 patience=10 scale=0.7 degrees=10 mixup=0.15 freeze=10 \
  imgsz=640 batch=8 name=fix-overfit
```

**别碰**：`dropout`、`erasing`、`auto_augment` —— 后两个**只对分类任务生效**，检测里改了等于没改。

### 12.3 欠拟合

**认法**：`train/box_loss` 降不下去、mAP 曲线仍在爬、`best` = 最后一轮。

| 顺序 | 改什么 | 具体值 | 为什么 |
|---|---|---|---|
| 1 | **加 epochs** | ×2，或 `resume=True` 续训 | 最常见原因就是没训完 |
| 2 | **减弱增强** | `mosaic=0.0 scale=0.2 degrees=0` | 增强太强，模型连训练集都学不会 |
| 3 | **提 imgsz** | `640 → 960` | 小目标欠拟合第一杀手 |
| 4 | **换大模型** | `yolov8n → yolov8s` | 容量不够 |
| 5 | 提 lr | **必须写 `optimizer=AdamW lr0=0.003`** | 见下方坑 |

```bash
yolo train model=yolov8n.pt data=datasets/leaves/data.yaml \
  epochs=60 mosaic=0.0 scale=0.2 imgsz=960 batch=8 name=fix-underfit
```

> ⚠️ **坑①**：`optimizer=auto`（默认）会**无视 `lr0`**——训练日志里会打
> `found, ignoring 'lr0=0.01'`，实际用的是 `AdamW(lr=0.002)`。想手调 lr 必须显式指定 `optimizer`。
>
> ⚠️ **坑②**：还有种“假欠拟合”——标签错、类别 id 错、图片损坏。loss 完全不降时，
> 先去看 `labels.jpg` + 抽 5 张图肉眼对，别急着加 epochs。

### 12.4 一个目标多个框

#### 30 秒定位法（不用重训）

```text
① conf 提到 0.6 → 还多吗？
     不多 → 假框：没收敛 / conf 太低 → 去加 epochs，别改训练参数
     还多 → ② iou 降到 0.5 → 还多吗？
              不多 → NMS 太松（默认 0.7 对密集目标偏松）
              还多 → ③ 两个框是同一类别吗？
                        是 → 标注里有重复框，去查 labels/
                        否 → agnostic_nms=True（跨类别也抑制）
```

```bash
yolo predict model=runs/detect/<run>/weights/best.pt source=data/samples/wobble.mp4 \
  conf=0.6 iou=0.5 agnostic_nms=True max_det=50
```

> 实证（本项目 11-3 记录）：同一片叶子出现两个框，**IoU = 0.624 < 默认 0.7**，
> 所以**逃过了 NMS**。→ `iou=0.5` 就能压掉。这类问题重训一遍是白费。

#### 训练端（确认不是 NMS 问题之后）

| 原因 | 改什么 |
|---|---|
| **模型没收敛**（最常见） | 加 `epochs`，看 `best` 是否还在最后一轮 |
| 数据里目标本来就重叠 | 加场景多样性；`mosaic` 会加剧重叠，可试 `mosaic=0.5` |
| 单类别被拆成多个类 | `single_cls=True` |
| 标注重复 | 查 `labels/` 里同图同类多框，删掉 |

### 12.5 漏检 / 误检 / 框不贴合

| 症状 | 推理端 | 训练端 |
|---|---|---|
| **漏检**（R 低） | `conf=0.15`、`imgsz=960`（推理时放大） | 补难例（遮挡/暗光/小目标）、训练 `imgsz=960` |
| **误检**（P 低） | `conf=0.5`、`max_det=20` | 补 20~50 张「无目标」背景图当负样本 |
| **框不贴合**（mAP50−mAP50-95 > 0.2） | — | 先查标注框是否贴合（`label_check.jpg`），再提 `imgsz` |
| **类别混淆**（混淆矩阵非对角亮） | `agnostic_nms=True` 治不了，只能重训 | 补两类各自的区分性样本 |

### 12.6 参数优先级（不知道先动谁就看这个）

```text
① epochs        ← 是不是没训完？一半问题在这
② imgsz         ← 小目标 / 延迟都靠它
③ conf / iou    ← 免费，先试
④ 增强（mosaic / scale / degrees / mixup）
⑤ freeze        ← 小数据集的过拟合特效药
⑥ 模型尺寸 n/s/m
⑦ lr / 损失权重  ← 最后才碰
```

### 12.7 三条规矩（就这三条）

| # | 规矩 | 原因 |
|---|---|---|
| 1 | **一次只改一个参数** | 改两个，涨了不知道是谁的功劳 |
| 2 | **改完至少跑 2 个 seed；这份数据上 Δ<0.09 一律当“没变”** | 实测同一配置换 seed，mAP50-95 抖 **±0.091**；`Δ<σ` 时你分不清是参数还是运气 |
| 3 | **先免费（推理参数）后付费（重训）** | 重训 1~2 分钟，改 conf 只要 1 秒 |

> 第 2 条的数据来源：`bench2-s0`~`bench2-s4` 五个 seed 的 mAP50-95 =
> 0.683 / 0.841 / 0.925 / 0.937 / 0.875 → **均值 0.852 ± 0.091**。
> 所以在这份数据上，**小于 0.09 的差异你不能下任何结论**。
> 想让这套流程分辨更小的差异，唯一的路是**加数据**（见第 10 节第 8 条）。
